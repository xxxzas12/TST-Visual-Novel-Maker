# TSTVN v1.0.8

## Feature
G. Point & Click (optional interactive scenes) — plus three bug fixes found while testing it.

## What Changed
- **New action "Point & Click"** (`pointAndClick`, Story/Flow categories). It sits next to the existing VN
  actions and replaces nothing.
  - **Fields:** a hint shown to the player, and a list of clickable objects (`Hotspot`).
  - **Each object has:** a name (shown on hover), an area (x/y/w/h in % of the stage), an optional image,
    a "when clicked, go to" target (continue / scene / label / action), an optional "set variable"
    (e.g. `has_key = true`), and an optional "only clickable if" condition.
- **Engine:** shows only the objects whose condition holds; on click it sets the variable and jumps.
  Hosts without point & click support get a normal Choice instead (graceful fallback).
- **Player:** objects are buttons on the fitted stage, so editor and game coordinates match.
  - Mouse: hover highlight and label. Touch screens (no hover): outlines and labels always shown.
  - Keyboard: Tab plus number keys. The hint appears in a banner.
  - Clicking elsewhere does not advance the story.
- **Editor:**
  - Properties panel: an object list editor.
  - Stage: when the action is selected, its objects are drawn as yellow boxes; drag to move, drag the
    corner to resize (snap honoured).
  - Integrated with existing systems: copy/templates (new ids), Story Flow arrows (deleting an arrow
    resets that object's target), validation, asset usage/replace/delete.
- **Bug fixes:**
  1. **Menu bar placement:** after leaving the title screen the in-game menu bar was squeezed against
     the right edge. It was measured while hidden (width 0) and not placed again.
     `setScreen('game')` now re-runs layout. Found on an E2E screenshot; the new assertion fails
     without the fix (bar 64px) and passes with it.
  2. **Template in the wrong language:** switching the editor language and creating a project right
     away could build the template in the old language. The main process applied the language only
     after writing `settings.json`, which can be later than the next request. It now applies it as
     soon as the request arrives (requests are handled in order).
     - The v1.0.1 serialisation alone did not fix this.
     - Verified with timestamped logging: in 18/18 repeated runs, "create" sees `th`.
  3. **EPERM saving settings:** `writeFileAtomic` failed with `EPERM` on Windows when the target was
     briefly open (another read, antivirus). The rename now retries transient EPERM/EACCES/EBUSY
     briefly, and gives up cleanly (no temp files left) on real errors.
     - This was the remaining cause of the intermittent Thai E2E failure (16/16 passes after the fix).
