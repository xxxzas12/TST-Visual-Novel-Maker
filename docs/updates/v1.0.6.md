# TSTVN v1.0.6

## Feature
E. Plugin Manager (new plugin system — none existed, see `docs/audit-v1.0.0.md` #8).

## What Changed
- **Plugin format** (`src/shared/plugins.ts`):
  - A folder (or a `.tstplugin` zip of it) with `plugin.json`: `id`, `name`, `version`, `author`,
    `description`, `contributes.themes` and `contributes.actionTemplates` (JSON files).
  - No code is executed, so a plugin cannot harm the editor or the user's files.
  - Manifests, paths (must stay inside the plugin), themes (normalized like `.tsttheme`) and action types
    are validated.
- **PluginStore** (`src/main/plugins.ts`):
  - Plugins live in `<userData>/plugins/<id>/`, and the disabled list in `state.json`.
  - Install validates everything in a staging folder before replacing an installed version (same id =
    update). It accepts zips with or without a top folder and is path-traversal safe.
  - Also: list (a damaged plugin shows its error and is skipped), enable/disable, remove, and loading the
    contributions of enabled plugins.
- **Plugin Manager UI** (`views/PluginManager.tsx`, Application Settings → 🧩 Plugins):
  - Installed Plugins cards (name, version, author, description, counts, enabled/disabled/damaged), an
    Enabled toggle, Remove (with confirmation), Install from file…, Install from folder… and
    📂 Open Plugin Folder.
- **Integration with existing systems** (nothing duplicated):
  - Themes view: section "From plugins". The themes are read-only like presets (Edit a copy / Save as
    Custom Preset / Export work). "Use for whole project" and "Use in scenes…" copy the theme into the
    project first, so games never depend on a plugin being installed.
  - "＋ Action → Templates" lists plugin templates (🧩, with the plugin name), inserted through the
    existing `insertActionTemplate`.
- Sample plugin `plugins/tstvn-sample-pack` (theme "Sunset Glow", template "Dramatic Entrance"),
  `plugins/README.md` and `scripts/pack-plugin.mjs`.

## Bug Fixes
- Enable/Disable checkbox now updates at once (optimistic), instead of waiting for the save — found by
  the E2E test ("clicking the checkbox did not change its state").

## Tests
- Unit `plugins.test.ts` (6):
  - Manifest rules.
  - Install from a folder; the content is loaded (theme completed with defaults, template with 3 known
    actions). Disable hides it, enable shows it again, remove deletes it.
  - Install/update from a `.tstplugin` with and without a top folder.
  - A broken update is rejected and leaves the installed version untouched. Non-zip and missing paths
    are rejected; a path-traversal zip writes nothing outside.
  - A damaged installed plugin shows its error and its content is skipped.
- E2E `plugins.spec.ts`:
  - Install the sample from a folder, then update it from a packed `.tstplugin` (still one entry).
  - Use the plugin theme for the project (it becomes an editable project copy) and insert the plugin
    template (3 actions).
  - Disable: the template and the plugin theme are hidden, the project's copy stays, and the project
    check is clean. Then Remove.
- Manual: "Open Plugin Folder" opened Explorer at the plugins folder.
- Gate: installer build OK, lint 0, unit 84/84, E2E 14/14 (incl. packaged app).

## UI Changes
- Application Settings → 🧩 Plugins. Themes → "From plugins". ＋ Action → Templates shows plugin templates.

## Compatibility
No project format change. Plugin themes are copied into projects as normal custom themes.

## Known Issues
- Plugins can contribute themes and action templates only (no code plugins, by design). Templates that
  reference assets need those assets in the project (validation reports missing ones).
