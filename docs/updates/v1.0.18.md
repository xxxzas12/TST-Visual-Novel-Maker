# TSTVN v1.0.18

UI/UX Phase 7: Style Library / reusable styles. This is the last phase of the UI/UX + Game UI
customization task.

## Added
- **Style Library**: reusable **Textbox styles** (dialogue box + name box) and **Choice styles**,
  saved in the project (`project.uiStyles`).
- A theme can be **linked** to a style (`textboxStyleId` / `choiceStyleId`). The style then replaces
  the theme's own dialogue/name box or choices, in the editor canvas and in the game.
- **Editing through any linked theme edits the style, so every theme (and every scene using those
  themes) updates.** Everything else (menu bar, menus, animations, text speed) stays per theme.
- **Edit only here**: the theme gets its own copy of the style and is unlinked (local override).
  Nothing changes on screen.
- Under the presets in the Dialogue Box / Choice Buttons sections:
  - a "My textbox styles" / "My choice styles" row (click to use the style);
  - "⭐ Save this textbox / these choices as a style…";
  - a link notice showing how many themes use the style, with "Edit only here".
- **📚 Style Library** window: every style with a preview drawing, "Used by N theme(s)", and
  Apply / Rename / Duplicate / Delete. Deleting a style gives its themes their own copy, so nothing
  changes in the game.

## Changed
- Edits in the Game UI editor are made on the theme as players see it and stored where they belong:
  the linked style or the theme.
- Export `.tsttheme` writes linked styles into the theme, so the file is self-contained.
- Style pictures (backgrounds, textures, frame images, button pictures):
  - count as used assets and are shipped with exported games;
  - show up in "where is this asset used";
  - are updated when an asset is replaced, and cleared when it is deleted.
- Fonts of linked styles are embedded like theme fonts (the used themes are resolved with their
  styles).

## Fixed
- (Found by this version's E2E test before release.) The new "My styles" list used an inline `[]`
  fallback in a store selector. That made the Themes view re-render forever and stay blank for
  projects without saved styles. It now uses a stable empty list.

## Compatibility
- Additive. Projects without `uiStyles` and themes without links behave exactly as before.
- Older TSTVN versions ignore the links and show each theme's own last stored look.

## Known Issues
- Styles are per project. Copying a style to another project is done by exporting a theme
  (`.tsttheme`) that uses it.
