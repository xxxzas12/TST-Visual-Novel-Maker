# TSTVN v1.0.3

## Feature
B. Fix text input bug (typing only one character, then the field had to be clicked again).

## What Changed
- **Root cause:** `PreviewFrame` called `iframe.focus()` every time it sent a game to the preview. The
  game-font preview on the settings page rebuilt its game on every project change. So each keystroke in
  Project name / Game title / Author restarted the preview and moved keyboard focus into the iframe.
- **Fix:** focusing the game is now opt-in (`autoFocus`). Only the Play window (`PreviewModal`) uses
  it, because there the game is what the user interacts with. Embedded previews (font preview, theme
  designer, theme "Try it") never take focus.
- v1.0.2 had already narrowed the trigger: the game-font preview now rebuilds only when what it shows
  changes. This version removes the cause itself, so no other preview can do the same.
- No input-specific workarounds (no refocusing, no uncontrolled inputs). Inputs keep their normal
  browser behavior.

## Files Changed
- Modified: `src/editor/components/PreviewFrame.tsx`, `src/editor/views/PreviewModal.tsx`,
  `src/editor/views/SettingsView.tsx` (test id for Author).

## Bug Fixes
- Text inputs lose focus after one character (Project Settings and any field next to a game preview).

## Tests
- New E2E `typing.spec.ts`: per-key typing, arrow keys, insertion in the middle, Backspace,
  Ctrl+Shift+Left selection + replace, clipboard paste, Thai via input-method commit. Fields: Welcome
  project name, Project name, Game title, Author, scene dialogue text, theme name. It also checks the
  values are saved in `project.json`.
- **Verified the test catches the bug:** with the original behavior restored (preview rebuilt on every
  project change + focus on every restart) it fails ("Expected: focused, Received: inactive"). With the
  fix it passes.
- Gate: installer build OK, lint 0, unit 75/75, E2E 12/12 (incl. packaged app). The Play window keeps
  keyboard control (acceptance test plays with keyboard and clicks).
