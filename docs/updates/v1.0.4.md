# TSTVN v1.0.4

## Feature
C. Installer redesign.

## What Changed
- `installer/installer.nsh` customises electron-builder's NSIS installer through its supported hooks
  (`nsis.include`). It doesn't replace the template, so registry, uninstaller, shortcut AppUserModelIDs
  and upgrades still come from electron-builder.
  - `customInstallMode`: always per-user (no admin), so the "for all users / only me" page is skipped.
    `allowToChangeInstallationDirectory: false` removes the folder page.
  - **Page 1** (`customPageAfterChangeDir`):
    - The header shows "TSTVN / Install TSTVN" with a large heading.
    - Two checkboxes, both ticked: *Create Desktop shortcut* and *Create Start Menu icon*.
    - A small "Installs to: …" line, and the button reads **Install**. There is no Back button.
  - `customInstall`: shortcuts the user unticked are removed right after electron-builder creates
    them, and the launch target falls back to the exe. `SetAutoClose true` goes straight to page 2.
  - **Page 2** (`customFinishPage`):
    - "TSTVN / ✓ Installed successfully" in green, and a **Launch TSTVN** button that starts the app
      as the user and closes the installer.
    - Only **Close** remains (no Back or Cancel).
  - Texts in English and Thai (LangString 1033/1054). Silent `/S` installs create both shortcuts.

## Files Changed
- Added: `installer/installer.nsh`, `scripts/test-installer.ps1`.
- Modified: `package.json` (`nsis.include`, `allowToChangeInstallationDirectory: false`, version),
  `README.md`.

## Bug Fixes
- First page showed an enabled "< Back" with nowhere to go back to: hidden.
- Without the MUI finish page the progress page sometimes waited on "Next >", and in that path TSTVN
  started although Launch was not pressed: `SetAutoClose true` makes the flow deterministic. Close
  verified not to start the app.
- Upgrading over an older install: verified that it keeps the shortcuts and the uninstall entry
  (v1.0.3 → v1.0.4, silent and interactive).

## Tests
- Real installer test (`scripts/test-installer.ps1`, run against the gate-built installer): **17/17**.
  - The first page has both boxes ticked and no Back button. The success page has Launch TSTVN.
  - Close exits without starting TSTVN.
  - Unticking Desktop creates only the Start Menu icon.
  - The Start Menu icon and the Desktop shortcut each open TSTVN when started through Explorer.
  - The install path is `%LOCALAPPDATA%ProgramsTSTVN`.
  - Uninstall removes files, both shortcuts and the registry entry.
  - A silent upgrade from 1.0.3 keeps the shortcuts (exe 1.0.4.0).
- Manual run: clicking **Launch TSTVN** started TSTVN and closed the installer. An interactive upgrade
  over 1.0.3 also passed. Screenshots are in `.e2e-tmp/installer/`.
- Gate: installer build OK, lint 0, unit 75/75, E2E 12/12 (incl. packaged app).

## UI Changes
- Installer reduced to two pages (Install / Installed successfully).

## Compatibility
- Same app id and install location, so existing installs upgrade in place, and projects and settings are
  untouched. Users who installed to a custom folder with an older installer are upgraded where
  electron-builder finds the previous installation.

## Known Issues
- "Clean environment" testing was done by uninstalling first. Windows Sandbox / a fresh VM is not
  available on this PC (Windows 11 Home).
- Shortcuts started from a terminal that has `ELECTRON_RUN_AS_NODE=1` (e.g. VS Code's) do not open the
  app. This is an Electron environment variable, not a shortcut problem; from Explorer, Start and the
  Desktop they work.

## Status
Stable
