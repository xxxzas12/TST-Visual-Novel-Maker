## Fixed
- **Startup race in editor preferences (preventive).** Application Settings are read in the background
  at startup. If the user changed one of these preferences before that read finished, the late result
  would have put the old value back:
  - resized or folded a panel, or picked a workspace;
  - saved a workspace;
  - switched Basic/Advanced.

  Choices made before the settings arrive are now kept (`changedPrefs` in `src/editor/store/ui.ts`).
  This race was found by reading the code while investigating the E2E failures below. It was **not** the
  cause of the E2E failures (see below); it is kept as a correct, low-risk fix.
- E2E workspace test: the drag helper waits briefly after pressing the mouse and moves in more steps, so
  it doesn't miss the first movements on a busy machine.

## Intermittent E2E failure — root cause found (test timing, not an app bug)
- After merging the GitHub changes, the full suite failed in uitheme 4 times out of 5 (the run that didn't
  failed in workspace instead), while it always passed alone.
- **Evidence:** the test was changed to record the page state and a screenshot at the moment of failure.
  The **Choice Buttons** were selected and had moved by about −161/−81 design px, which is exactly the
  test's −60/−30 screen-px drag at the canvas scale.
- **Cause:** the test changed the dialogue box width and immediately dragged the centre of its selection
  box. On a busy machine the selection boxes are re-measured a moment later, so the drag used the old
  box, whose centre lay under the choice buttons. A person cannot act within that moment, so the app
  behaves correctly.
- **Fix (test only):** `e2e/uitheme.spec.ts` now waits until the selection box shows the new 1600 px width
  before dragging.
- Theories tested and disproved along the way, so not applied:
  - the name box covering a narrow dialogue box;
  - a minimized or covered window pausing rendering.
- The earlier one-off workspace failure (a drag moved 38 px instead of 100) is the same kind of drag
  timing. The workspace drag helper now waits after pressing and moves in more steps.
