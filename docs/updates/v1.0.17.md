# TSTVN v1.0.17

## Feature
UI/UX Phase 6: Advanced animation controls.

## Inspection (before changing anything)
- v1.0.16 already stores every animation value (`AnimSpec`: delay, direction, distance, start
  scale/rotation/opacity, stagger), and the runtime and preview already use them.
- Only presets, duration and easing could be edited, so this phase adds the controls. There is no
  second animation system.

## What Changed
- `AnimControl` (`src/editor/views/themes/AnimControls.tsx`) gets an Advanced block, shown only in
  **Advanced** mode:
  - **Delay**;
  - **Direction** (↑ ↓ ← →, for slide and bounce; the preset list follows, e.g. Direction → Right
    shows "Slide from Left");
  - **Distance** (slide, bounce, shake);
  - **Start size** (pop, scale, pulse);
  - **Start rotation**;
  - **Start opacity**;
  - **⟲ Back to the preset's values**, shown only when something was changed.

  Help marks explain distance, size and opacity.
- Choice Buttons: **Time between buttons** (Advanced, when "One after another" is on).
- Used everywhere AnimControl is: dialogue box Appear/Disappear, choice Appear, and the theme
  overview.

## Tests
- Unit `uianim.test.ts` +1: direction, distance, start rotation, size and opacity reach the
  keyframes, and the preset name follows the direction.
- E2E `animation-advanced.spec.ts`:
  - Basic has no fine controls.
  - Advanced: Slide → direction Right, 200 px, delay 0.5 s, 15°, start opacity 0.5, 1 s.
  - The canvas animation has exactly that delay, duration, first keyframe
    (`translateX(-200px) rotate(15deg)`, opacity 0.5).
  - Choices pop in 0.2 s apart (delays 0/200/400/600 ms).
  - "Back to the preset's values" restores size 0.6 and hides itself.
  - In the game the dialogue box animation has the same timing.
  - Values are saved.
- Gate: installer build OK, lint 0, unit 125/125, E2E 25/25 (incl. packaged app) — clean on the first run.
