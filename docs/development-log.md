  the Store stub; .NET SDK 9/10 present.
- **Action**: installed Node.js **v24.21.0 LTS** as a portable, user-scope copy
  (`%LOCALAPPDATA%\Programs\node-v24.21.0-win-x64`, SHA-256 verified, added to the user PATH; no admin).
- **Git**: not available, so no repository/commits were created (spec §64: "if Git exists").

## Phases 20–23 — Mobile, Automated Testing, Performance, Polish

- **E2E** (`e2e/`): Playwright drives the real Electron editor and the exported game.
- **Errors found by the tests → root cause → fix**
  1. `electron.exe: bad option --remote-debugging-port` → the VS Code host sets `ELECTRON_RUN_AS_NODE=1`, which
     child processes inherit. Fixed in the test launcher, `npm start` (new `scripts/start.mjs`), `npm run dev`
     and the editor's "Run Game" spawn.
  2. Chapter "＋ add scene" was hover-only (not keyboard accessible) → always visible; other row tools also show
     on `:focus-within`.
  3. **Runtime bug**: the CG layer (z-index 400) covered the title screen and dialogue UI → `.tvn-scene` now
     creates its own stacking context.
  4. **Runtime bug** (found by inspecting screenshots, not by an assertion): themes were never applied —
     `el.style['--var'] = …` is ignored by browsers for custom properties → `applyStyle` uses `setProperty`.
     Added an E2E assertion on the computed name-box color.
  5. Ctrl+S in game advanced a line (Ctrl = skip) → skip now starts after holding Ctrl 300 ms; Ctrl+S opens Save.
  6. Save-slot screenshots were empty in the editor preview (cross-origin canvas taint) → preview loads images
     with CORS; E2E asserts a screenshot exists in preview **and** in the exported Windows game.
  7. Teardown dialog protocol error → in E2E mode only, the renderer doesn't block unload (the main process
     already allows it); recovery snapshots are still written.
  8. Lint findings fixed at the source (useless assignments, control-char regex, error `cause`, hook naming,
     shadowed `screen` global).
- **Performance**: 2 000 assets imported in ~22 s (hash + copy + thumbnails), search 60–110 ms, 40 DOM tiles.
- **Mobile**: exported game verified at 844×390, 390×844 and 1024×768; Web export verified at 390×844
  (dialog inside the viewport, no horizontal overflow).
- **Packaging**: `npm run dist` → `release/win-unpacked/TSTVN.exe`; `e2e/packaged.spec.ts` confirms the packaged
  editor exports a game that runs (and that no editor files leak into it). Runtime libraries moved to
  devDependencies since everything is bundled.

## Update — Thai / English language + installer

- **Built**: `src/shared/i18n.ts` (English text is the key) + `i18n-th.ts` (≈900 Thai strings), language switch on
  the start screen and in Settings (saved in app settings; first run follows the OS locale), keyed re-render of
  the whole editor; validation/export messages and template stories translated (main process shares the
  dictionary); per-project **game language** with a small runtime string table (`runtime/player/strings.ts`) so
  exported games show Thai menus. Action search also matches Thai names.
- **Method**: a one-off TypeScript-AST codemod wrapped ~630 JSX texts/attributes/toasts/dialog strings in `tr()`;
  fragments split by JSX expressions were then rewritten as whole sentences with `{0}` placeholders.
  `scripts/i18n-keys.mjs` extracts every key; `tests/i18n.test.ts` fails if any key lacks a Thai translation or a
  translation changes its `{placeholders}`.
- **Installer**: NSIS per-user installer (`TSTVN-Setup-1.0.0.exe`, EN/TH, choose folder, Desktop + Start Menu
  shortcuts) and a generated app icon (`scripts/make-icon.mjs`). Exports now skip the installer's
  `Uninstall TSTVN.exe`. The installer was installed silently on this PC and `e2e/packaged.spec.ts` was run
  against the installed copy (`TSTVN_EXE=%LOCALAPPDATA%\Programs\TSTVN\TSTVN.exe`).
- **Errors → fixes**: action-list names stayed English (read from the catalogue, not literals) → wrapped;
  intermittent Story-Flow E2E failure traced with hit-testing to the onboarding panel covering the drag handle
  (the test raced the async checklist) → feature tests start with onboarding dismissed and wait until handles
  are the topmost element. Verified 10/10 isolated + 2 full `test:all` runs.

## Update — Font system + Light/Dark appearance

- **Built**:
  - **System fonts:** `src/main/fonts.ts` reads family names from the font files themselves (OpenType `name`
    table, `.ttf/.otf/.ttc`) in the Windows and user font folders.
  - **Imported fonts:** `FontStore` keeps them in the app's user data (no Windows installation). It serves them
    to the editor through a new `tstvn-font://` protocol and embeds them into projects (`fonts/`).
  - **Editor side:** a font picker (search, per-font rendering, live preview, Import/Remove), and
    `FontSettings` with draft state, Dark and Light samples, a live game preview, and Apply / Cancel /
    Reset to Default.
  - **Settings:** UI font and size are saved in the app settings (old `uiScale` is migrated). Dialogue font and
    size are saved per project; `buildGameData` overrides the theme font and size.
  - **Runtime:** loads embedded fonts with `@font-face`.
  - **Export, validation, packages:** export copies and verifies font files, validation reports a missing font
    file, and `.tstvn` packages include `fonts/`.
  - **Light mode:** a light palette and Appearance setting (Dark / Light / Follow Windows); hard-coded colours
    moved into variables.
- **Tests**:
  - `tests/fonts.test.ts` builds a real test font by renaming the family inside `arial.ttf`
    (`scripts/font-tools.mjs`, "TSTVN Test Font", which exists nowhere on the system). It covers parsing,
    system listing, import/dedupe/reject, embedding, game data, export and missing-file validation.
  - `tests/appearance.test.ts` checks WCAG contrast of both palettes from `styles.css`.
  - The E2E `fonts` test:
    - picks Arial and changes sizes, and checks the preview updates while the UI is unchanged until Apply;
    - imports the test font through the picker, uses it in the live game preview, and checks
      `document.fonts.check` returns true;
    - applies, switches to Light mode, exports, and checks the font is loaded in the exported game;
    - restarts and checks every setting persisted, then Reset to Default.
- **Errors → fixes**:
  - Custom themes are frozen project state, so the theme is cloned before the font override.
  - Chromium serializes single-word font families without quotes, so the test patterns were relaxed.
  - A light-mode screenshot showed grey buttons. Computed styles proved it was the 0.12 s background transition
    caught mid-way, not a palette bug.
- **Build/Release**: installer rebuilt, installed on this PC (upgrade), packaged test passed against the
  installed copy, and `TSTVN-Setup-1.0.0.exe` was copied to the Desktop.

## Update — Game UI / Theme editor

- **Theme model v2** (`shared/types.ts`, `shared/themes.ts`):
  - **Dialogue box:** anchor, X/Y, width, minimum height, padding, surface, text, text speed.
  - **Name box:** on/off, inside the box or on its edge, alignment, offset, minimum size.
  - **Choices:** group position, width/min width/height, spacing, Normal/Hover/Pressed/Disabled styles,
    hover/press animations.
  - **Menu bar:** position, direction, and a list of buttons with actions (Auto, Skip, Save, Load,
    Settings, Hide, Menu).
  - **Shared:** menus, fonts (system or embedded per element), and accessibility limits. A surface is
    color + image (stretch/cover/contain/tile) + opacity + border + radius + shadow + blur.
  - Sizes are design px on a 1920×1080 canvas, or `%`/`vw`/`vh`.
  - **Presets:** Modern, Minimal, Classic, Dark, Soft, RPG, Romance, Horror, Fantasy.
- **Migration:**
  - Version-1 themes are converted on load: sizes ×1.5 from 1280×720 "UI points", single colors
    become state styles, `position` becomes an anchor.
  - `ProjectSettings.uiVersion` stops a second migration of `dialogueFontSize`.
  - `normalizeTheme` repairs damaged or hand-edited theme data by type-checked deep merge.
- **Layout engine** (`shared/uilayout.ts`):
  - The runtime and the editor share it: scale factor, unit conversion, readable font floor ×
    player text size, and placement clamped to the safe area.
  - Bottom-anchored boxes grow upwards and scroll instead of clipping. Choices get the free band next
    to the dialogue box.
  - The safe area is a CSS variable (`--tvn-safe-*`), so the editor can simulate notches.
- **Runtime:**
  - Every dialogue/name/choice/menu style comes from theme variables; `runtime.css` no longer hard-codes
    them.
  - Scene theme overrides switch through a new `RuntimeHost.sceneChanged`.
  - Menu bar buttons are built from the theme; added a Skip toggle.
  - Choice options can be shown disabled ("show when locked").
  - Player settings gained **Text size** and **High contrast**.
- **Editor** (`views/ThemesView.tsx`, `views/themes/*`):
  - The real runtime runs in design mode (all elements and choice states at once) inside a
    device-sized, scaled iframe.
  - An overlay offers select, drag, resize handles, align, keyboard nudge, and duplicate/delete of
    menu buttons. The properties panel covers each element.
  - Device switcher (6 presets) and a layout check across all devices: overflow, overlap, contrast,
    touch size.
  - "Try it" mode, presets are read-only (Edit a copy / Save as Custom Preset), and theme rename and
    delete.
  - "Use for whole project" / "Use in scenes…" plus a 🎨 scene theme menu in the Scenes view.
  - `.tsttheme` export/import (`main/themeIO.ts`): a zip with theme.json, images and fonts. Images are
    imported as assets under `assets/UI/Themes/<name>/`, and identical images are reused.
  - Theme images take part in asset usage, replace and remove; validation reports missing theme fonts
    and missing scene themes.
- **Errors → root cause → fix**:
  - The layout check found that several new presets failed WCAG 4.5:1 (e.g. white on `#4f6bff`,
    see-through menu bars). The colors were tuned, and a unit test now requires every preset to pass.
  - Menu bar wrapped into 3 rows on desktop (seen in an E2E screenshot): the bar was measured while
    still absolutely placed near the right edge, so it shrink-wrapped. It is now measured at the
    top-left before placing.
  - Intermittent "Thai template created in English" in the full E2E run: `app:setSettings` did an
    unserialized read-modify-write, and it reset the main-process language from whatever it had read.
    Writes are now queued, and the language only changes when the patch contains one.
  - E2E races: the test measured the exported game before its first line appeared, and it assumed
    the romance template had named speakers. The tests now wait for text and check the dialogue box
    instead.
- **Build/Release:**
  - The installer was rebuilt and copied to the Desktop.
  - A silent upgrade over the old install removed the old version but did not register the new one
    (no shortcut or uninstall entry). A clean silent uninstall followed by a fresh install fixed it.
  - The packaged test passed against the installed copy.
